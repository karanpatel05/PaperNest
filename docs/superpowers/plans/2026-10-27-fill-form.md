# Filling a PDF form — Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement inline; final fresh-context review.

**Goal:** The Tools screen's *Fill Form*, ledger row 24. The pass-through slice established that an unedited page keeps a field widget and its `/T` name, but that PaperNest writes **no document-level AcroForm** — and the synthetic fixture had none either, so nothing was known about real forms. Row 24 stayed Planned for exactly that reason.

## Two findings that unblock it
**1. A real AcroForm can be hand-built.** PDFKit cannot create one, so the fixture is written as raw PDF bytes with computed xref offsets: 882 bytes, catalog `/AcroForm << /Fields [...] >>`, one `/FT /Tx` widget named `customer`. Core Graphics reads it as `[("customer", "")]`, so it is a genuine form rather than a loose widget.

**2. PDFKit preserves an AcroForm it did not create.** Setting `widgetStringValue` and writing gives, read back through **Core Graphics**: `[("customer", "Jane Appleseed")]`. That matters because PDFKit reports a `fieldName` whether or not a form exists — it misled this project once already — so the check goes through CG every time.

Those two together are the whole reason this is buildable. The earlier conclusion ("PaperNest writes no AcroForm") remains true and is a different statement from "PDFKit cannot keep one".

## Constraints and review focus
- **A name that is not in the form is refused, never ignored.** Silently dropping an unknown field would let a caller believe a value was written that is not in the file.
- **A PDF with no AcroForm has no fields, and filling one is refused.** Most PDFs PaperNest itself produces are in exactly that state, so this is the common case, not an edge.
- **Only text fields are filled.** Checkboxes and choice fields need appearance-state handling that is not in this slice; `fields` still *reports* them, with their type, so a caller can say "this form has parts I cannot fill" instead of pretending the form is done.
- **Filling does not flatten.** The field stays a field and remains editable by the next reader. That is what filling a form means, and a caller must not describe the result as locked.
- Every assertion about what a filled file contains is read through Core Graphics, not PDFKit.
