## Work division — read this before you touch anything

Two agents share this one working tree. On 2026-10-22 both were editing it at the same time and a `git add -A`
swept Codex's in-flight work into commit `5abebea` under a Claude message. Codex recorded the same event from its

### Rules for both of you

1. **Claim your files in "Current claims" below before you edit them.** First run `ls -lT` on them. If anything
   changed in the last few minutes, stop and re-read this page: the other session may still be running.
2. **Never `git add -A`.** Stage by explicit path, and only paths you wrote.
3. **Committing.** The owner said **"Commit each"** on 2026-10-28, so Claude now commits each finished slice as
   it goes without asking. That replaces the earlier rule for Claude only — it is not a licence to commit the other
   session's work, so rule 2 still governs *what* goes in: stage by explicit path, and for `docs/TEST_MATRIX.md`
   and this file, which both sessions write, build the blob from `HEAD` plus your own edits rather than committing
   the whole file. The branch is `document-tools-ocr-and-file-items`. **Since 2026-11-13 there is a remote:** `origin` is
   `https://github.com/karanpatel05/PaperNest`, **public**, pushed at the owner's request. `main` was
   fast-forwarded to this branch the same day (both at `6bf87ca`). Committing does not push; push only when the owner asks.
4. **Verify before you claim anything works**, and record the real outcome in `docs/TEST_MATRIX.md`. Never mark an
   unrun check as passed.
5. **Shared files** — `Localization.swift`, the three `Localizable.strings`, `Apps/iOS/UITests/AppUITests.swift`,
   `scripts/ui-test-ios.sh` — are touched by nearly every slice. Add keys in the same change as the code that uses
   them, in a block commented with your slice name, and append UI tests at the end of the file without reordering
   the existing ones.

**What "Codex tests the whole app" does and does not move.** It moves app-level verification: whether a feature
works in the running app, on each platform, in each language, for someone using it. It does **not** mean backend
code arrives untested — Claude still writes the unit and store tests for its own logic, because test-first is how
that logic gets built and an engine slice with no tests is not finished. The division is *which kind* of testing,
not whether Claude tests.

**A standing consequence worth naming.** Backend work now routinely lands with no UI attached: compression and
plain-text export both work and are unreachable in the app. That is the expected shape of this split, not an
oversight, and it puts a duty on both sides — Claude says plainly in TEST_MATRIX when a slice has no UI, and a
tool or action appears in a screen only once it really works. The rule against disabled marketing tiles still
stands.

Most slices span both. The agent who owns the **workstream** writes the thin layer it needs on the other side and
says so in Current claims — that is how the ZIP work below has a `LibraryModel.extractArchive` in it, and how the
file-preview work has a `FileKind.prepareTemporaryCopy` in it.

## Traps found the hard way — read before touching these
- **Quick Look caches thumbnails, so a probe that reuses a filename can report an older picture.** Measuring whether the requested size is a bound, a second request for a file already thumbnailed at 200×200@2x answered 400×400 for a 120×400 box — which looked like "the size is ignored and may exceed what you asked for". It is not: with a **fresh name and fresh bytes per request**, 120×400 gives 120×120 and 64×64@2x gives 128×128, so it really is a bound. Give every probe and every test its own UUID filename *and* unique contents, or the cache answers for you. `FileThumbnailTests` does this deliberately.
- **Blocking in synchronous XPC on several of Swift concurrency's cooperative threads at once deadlocks, and PDFKit does it behind your back.** Reading a page's `.annotations` makes PDFKit build each widget, and building one makes it resolve the font named in the field's `/DA` — `/Helv` in most forms Acrobat writes, which is no real PostScript name, so CoreText goes looking for it over synchronous XPC. Measured: eight concurrent `PDFForm.filled` calls finish in 0.066s on plain `Thread`s and **never finish** in a `withTaskGroup`, not one of them. The suite's symptom is the worst kind — the build succeeds, then *no test output at all*, forever — because the starved pool cannot run the harness either. `/usr/bin/sample` on the stuck process is what found it; count the lock-wait frames too, since "nine unanswered calls" and "one stuck call with eight waiters" are different bugs (it was the former: 0 lock frames). `PDFForm` now holds an `NSLock` across its PDFKit work. **The trigger is reading `.annotations`, and only that** — probed at 16 concurrent callers each, `page.copy()`, `page.string` and `outlineRoot` all finish while `page.annotations` hangs. So copying a page in `Compression`/`Exporter` is *not* exposed, `PageRenderer` is pure Core Graphics, and `PDFForm` is the only code in `Sources` that reads `.annotations`, so the lock covers the product. An earlier version of this note said the opposite; it was a guess from a grep. The app fans out heavily (87 `Task {}`/`.task {}` sites in `PaperNestUI`), so this was worth measuring rather than assuming. Same shape as the Vision hang on 2026-10-26.
- **Text with a NUL used to be truncated on the way into SQLite — fixed on 2026-10-26, and the note is kept because the shape of the bug is worth knowing.** `bind` passed length `-1` to `sqlite3_bind_text` and `Statement.text` read with `String(cString:)`, so both directions stopped at the first NUL. Both now pass explicit byte counts. If you add a text path, do not reintroduce `-1` or `String(cString:)`. A NUL can now be *stored*, so strip control characters where text is rendered or written into another format, as the DOCX writer does — that is presentation, not storage.
- **Killing a build leaves debris in the shared build cache.** A `swift-test` killed mid-build left a corrupted `PaperNestImportTests.xctest`, and hours later an unrelated run failed with `codesign: invalid or unsupported format for signature`. Delete the named bundle under `~/Library/Caches/PaperNest/build-<hash>/out/Products/Debug` rather than hunting for a code cause.
- **An encrypted PDF reopened for editing is *locked*, and a locked document yields blank pages.** `replaceWithSourcePages` reopens the file the context just wrote and copies every page that did not pass through out of it. With a password that file is locked, so a mixed document came back with its drawn pages blank **and its title gone**, while the passed-through page looked perfect. It now unlocks `drawn` before copying. Third instance of this same shape in two days: compression's blank scans, compression's blank protected PDFs, and this.
- **The export password must be ASCII, and Latin-1 is not the boundary.** Measured: `"été-Ñandú-2026"` failed to write although every character is Latin-1, and PDFKit refused `"contraseña-密码-1"`. Non-ASCII is refused up front with `ExportError.passwordNotRepresentable`. Only the first 32 bytes are honoured, so a 32-character prefix opens a file written with 44 characters; a test pins that so the documented limit cannot go stale.
- **Anything that re-writes a finished PDF drops its encryption — re-apply the password there too.** `writePDF` encrypts through the `CGPDFContext` info dictionary, but pass-through then assembles the document in PDFKit and writes it to a staged file, which replaces the encrypted one. Without `.userPasswordOption` / `.ownerPasswordOption` on *that* write the export arrives unprotected while the caller believes it is protected. The same shape as compression stripping an owner's restrictions. A test exports an untouched page with a password and checks the result is still encrypted.
- **Set the owner password as well as the user password.** A PDF opens with *either*. Set only the user password and the file opens with an empty owner password, so the protection is no protection at all. Both are set to the same value, and a test asserts an empty password does not open the file.
- **A copied `PDFPage` is read lazily from the document it came from.** Let that document go out of scope and the page serializes **blank** — and a blank page is the smallest file of all, so a compression test asserting only `isSmaller` passes: 869 bytes from a 193 KB scan, looking like a triumph. All three sites now hold their sources with `withExtendedLifetime` rather than trusting scope, because every run here is Debug and the optimizer may release after last use.
- **A locked PDF reports no text, so every page looks like a scan.** `page.string` is nil, `carriesText` is false, the locked `CGPDFDocument` draws nothing, and the resulting white page beats any size budget: 845 bytes from 8,110, one grey level, reported as a 99% saving. Compression therefore refuses an encrypted or locked PDF outright. The same refusal covers an owner password that only restricts copying, because assembling the output fresh drops the restriction and would hand back an unrestricted copy. **Documents are not affected** — `SourceInspection.unlockedCopy` stores a decrypted copy at import and verifies `!check.isEncrypted`, so the export path never sees an encrypted asset.
- **Size a rasterized PDF page from the *upright crop box*, never PDFKit's media box.** `drawPDFContent` scales content to the upright crop box and applies the page's rotation. A `/Rotate 90` page — an ordinary landscape phone scan — has a portrait media box, so taking that size squeezes 792×612 of content into a portrait bitmap and puts it on an unrotated portrait page: the input rendered 396×306 and the output 306×396. Use `PageGeometry.uprightPDFSize(box:rotationDegrees:)`.
- **A PDF assembled *in place* loses form-field names; assemble it fresh.** `writePDF` draws placeholder pages and then swaps in copied source pages. Done by editing the document opened from the `CGContext`-written file, a widget's name came back `text5`, `text10` — a different invented name each run — because a field's name lives in the document-level `AcroForm` and that file has none. Built into a new `PDFDocument` with `documentAttributes` carried over, the same copy keeps `customer`. Traced stage by stage before being believed; the first diagnosis ("PDFKit regenerates names, so this cannot be done") was wrong, and a probe of the fixture alone is what made it look right.
- **PDFKit reports a widget's `fieldName` whether or not the file has a form dictionary.** So an export test that reads `fieldName` back through PDFKit cannot tell a real interactive form from a bare widget annotation. Check the catalog's `AcroForm` through Core Graphics (`CGPDFDictionaryGetDictionary(catalog, "AcroForm", …)`) when the claim is about forms. Our synthetic fixture has no `AcroForm` at all, which is why ledger row 24 is still Planned.
- **Pass-through must stand down for a page being re-encoded, and the guard has to stay ahead of the pass-through branch.** In `writePDF` that is `if reEncoded == nil, let copy = sourceCopy, untouchedCandidate`. A copied page ignores the preset entirely, so if that ordering is lost, compression silently stops working for scanned PDFs and every preset hands back the same bytes — the exact bug this fixed. A page that **carries text** still passes through under compression, on purpose: it is drawn as vector whatever the preset, so copying costs nothing and keeps its links. **And a re-encode is kept only when it is smaller than the page it replaces,** measured per page by writing the copied page alone into a document (`byteCount(of:)`). Not as a share of the file: a document of one photograph and nine blank pages has no useful average — the blank pages would be allowed to grow and the photograph refused. Light (300 dpi) upsamples most scans and measured 416,360 bytes against a 193,043-byte page before this guard existed.
- **A refusal test that does not get its refusal leaks a temporary directory.** `await #expect(throws:)` around an export has no `defer` to clean up, so when the export unexpectedly *succeeds* its `ExportOutput` is left in the shared temporary root — and the next run of `cancellingKeepsTheLibraryIdleAndLeavesNoArchiveBehind` fails on it. That happened again on 2026-10-27, from a test of mine; the directory's UUID matched the earlier failure's output exactly. List the directory and match the UUID before suspecting the code.
- **`Exporter.temporaryRoot` defaults to the process-wide temporary directory, which every test shares.** A test that counts or asserts on its contents is measuring every other test running in parallel, not itself; `cancellingKeepsTheLibraryIdleAndLeavesNoArchiveBehind` also fails on residue left by any earlier crashed run. Two false failures have come from this. Pass `Exporter(renderer:temporaryRoot:)` a directory the test owns, and always remove an `ExportOutput` you create.
- **Never call `TextRecognizer.recognize(_:)` from an actor or a `Task`.** Vision's queue dispatches synchronously, so it parks the calling thread until Vision has capacity. On the Swift concurrency cooperative pool that is one thread per core, and enough concurrent recognitions park all of them, including the ones Vision needs to finish — the process deadlocks. One full test run hung for four hours this way. Use `recognizeOnADedicatedThread(_:)`. Reproduces at 16 concurrent passes on 8 cores; six was not enough, so a passing small test proves nothing here.

- **The title menu's button is labelled `"<name>, Actions Menu"`.** Match it by label prefix with an existence check. An exact match on the name misses it, and the `staticTexts` fallback is not reliably present — a test written that way passes on luck.
- **Restart the simulator before investigating a spread of unrelated UI failures.** One run showed three, including an app that would not launch at all; all passed after `simctl shutdown` and a clean boot.

- **QuickLook supplies its own Done button only when it presents itself.** Inside a SwiftUI sheet or cover, SwiftUI owns the presentation, so install the dismissal yourself (`file-preview-done`).
- **Temporary copies have an owner.** Await `FileKind.prepareTemporaryCopy`, retain its `PreparedFileCopy` for the entire preview/share/save lifetime, and let it clean up its own directory on release. Do not delete on `onDisappear`: child presentations can cover the parent. Info reuses the preview copy. Never give Quick Look the immutable asset path.
- **Recent previews belong to RootView.** A presentation modifier on the empty List sections in `LibraryHomeSections` did not present. The home callback now sets `RootView.homeFilePreview`.
- **A known Simulator flake:** *"test runner exited with code 0 before establishing connection"* fails a run before any test executes. Rerun once before investigating; it has never reproduced twice in a row here.

- **Migrations that rebuild a table.** This store runs `PRAGMA foreign_keys = ON`, so `DROP TABLE items` performs an implicit delete that **cascades into `pages` and empties the library** (reproduced: *pages before 2 → after 0*). Mark such a migration `rebuildsTables`; the runner disables foreign keys around it and verifies `PRAGMA foreign_key_check` inside the transaction. Never hand-roll a rebuild.
- **Recognised text is indexed only when `.completed` *and* `sourceRevision` matches the page.** Ordinary edits (rotate, crop, ink) keep the text findable; `replacePageContent` clears it, because a rescan puts different paper on the page. Do not widen this to every revision bump — an existing composition test depends on it.
- **The OCR text layer must be drawn in source space** with the page transform concatenated onto the CTM. Placing lines by their page-space bounding box collapses a rotated page's text into slivers.
- **`CTLineDraw` overrides `CGContext.textMatrix`** from the line's own runs. Any horizontal stretch belongs on the CTM.
- **A dynamic UTI is never stored.** The system invents one for an unknown extension; it means nothing after sync, so those files are recorded as `public.data`.
- **`LibraryView.importableTypes` is now every type.** Add Pages and Replace Page must keep using `LibraryView.pageTypes`, or a video could be picked to replace a page.
- **The iPhone document toolbar has no ⋯ menu** — only iPad and Mac do. Document actions go in the bottom bar's ⋯ there. Each layout has exactly one overflow menu.
- **The iPhone home has no vertical room left.** A third large button in `CaptureActions` pushed the Folders **+** off screen and broke a test. Put new entry points in the toolbar.
- **SwiftUI menu items do not expose `accessibilityIdentifier`** to XCUITest; match them by label. A `LabeledContent` row is one element labelled `"<label>, <value>"`. The title menu's button is labelled `"<name>, Actions Menu"`.
- **swift-testing reports a failure when an optional inside a `#expect` expression is nil**, even when the condition is true. Bind `pdf.page(at:)?.string` to a local first.
- **Deliberate contract change:** importing a `.txt` no longer fails as "unsupported type"; it becomes a file item. The M1 gate test asserts the new behaviour.
